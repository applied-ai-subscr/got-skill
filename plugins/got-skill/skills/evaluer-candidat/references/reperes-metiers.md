# Repères métiers pour préparer les questions

Repères génériques pour formuler des questions et juger les réponses. Les exigences du besoin client restent prioritaires.

## Business analyst front office (finance de marché)
Compétences : recueil et formalisation des besoins, processus front-to-back, produits financiers (actions, taux, dérivés), positions et risques, user stories, critères d'acceptation, UAT, SQL, communication métier-IT. Questions types : décrire une fonctionnalité livrée de bout en bout, un plan de test détaillé, un incident analysé, un arbitrage entre contraintes métier et techniques ; expliquer le cycle de vie d'une transaction et les acteurs front, middle et back office ; citer les risques de marché, de crédit, de liquidité et opérationnels et le cadre réglementaire applicable. Vérifier toute information réglementaire récente.

## Data engineer
Compétences : ingestion, transformation, modélisation, qualité, SQL, traitement distribué, orchestration, observabilité, sécurité, gouvernance, optimisation. Questions types Spark : évaluation paresseuse, transformations et actions, partitionnement et shuffles, broadcast join, cache et persistance, plan d'exécution, gestion d'un skew ; orchestration : DAG, dépendances, reprises, alerting ; qualité : tests automatisés, traçabilité ; sécurité et accès aux données.

## DevOps et plateforme
Compétences : CI/CD, infrastructure as code, gestion de configuration (Ansible ou équivalent), conteneurs, orchestration Kubernetes, observabilité, gestion des secrets, documentation, support de production. Questions types : qui utilise ses pipelines et comment il les administre (droits, support), stratégie de rollback, cohérence de configuration entre environnements, sécurisation des secrets, analyse statique, métriques à surveiller en production, gestion des logs.

## Développement Java back-end
Compétences : conception d'API et services, Java et framework applicatif, persistance, tests, sécurité, performance, résilience, observabilité, livraison continue. Questions types : décisions d'architecture argumentées, optimisation mesurée, évolution compatible d'une API, gestion des erreurs et des transactions.

## Développement front-end React
Compétences : composants, état, hooks, TypeScript, appels d'API, accessibilité, responsive design, performance, tests, migration progressive d'un legacy. Questions types : compromis de conception, gestion des erreurs réseau, mesure et amélioration des performances, stratégie de tests, outillage (bundler, linter, CI).

## Pour tout rôle
Demander un exemple concret : contexte, responsabilité personnelle, action, difficulté, résultat mesuré, apprentissage. Faire varier une contrainte (volume, panne, sécurité, délai, dette legacy) pour tester la profondeur. Signaux d'alerte : réponse théorique, rôle personnel absent, choix inexpliqués.
